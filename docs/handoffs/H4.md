## What changed for a learner

Nothing visible, by design. Answering a predict or check card (tap, typed or spoken) now records
one `Observation` per question. The feedback turn starts as before. Capture adds a median 1.7 ms
(SQLite, this laptop) before the provider call, and labeling runs in the background.

One small visible effect: free answers are now graded by the deterministic verifiers before the
tutor sees them.
- `25/3` for a key of `8.333` and `2(x+1)` for `2x+2` are now `correct` instead of `unverified`.
- A numeric mismatch is now `incorrect`.
- When the key audit finds the tutor's key wrong, the tutor is told so (`key_audit` in THIS TURN)
  and the learner is graded against the recomputed value.

## Design as built

- **Capture** (`tutor_router.record_evidence`):
  - It runs after `store.begin` claims a new answer turn, never on a replay, and before the context
    packet and provider call.
  - It writes one `learning_observations` row in a short transaction, then starts labeling with
    `observations.start` (an `asyncio` task, the same pattern as image jobs).
  - Any capture error is logged by type only and never reaches the lesson.
- **Dedupe**: `UNIQUE(session_id, qid)` with insert-or-get. A repeat increments `duplicates` and
  schedules nothing; the first answer stands. This covers a replayed turn id, a double submit, and
  a re-answer after a feedback turn that failed before drawing (which leaves the card open).
- **Provenance**:
  - Only `kind=answer` turns create rows. The single `EvidenceSource` is the answer turn id, the
    SHA-256 of the exact answer text, the modality and `author=learner`.
  - The question, options and key are stored as labeler context (`question_json`), never as a
    source. They are left out of the evidence route's response.
  - `via=ink` needs `element_ids` whose board records are all `creator=human`; anything else is a
    422 `evidence_not_learner` before any claim. `element_ids` without `via=ink` is a 422.
- **Verifiers** (`observations.py`):
  - An option match for predict and mcq.
  - An exact case-folded match for free text.
  - Numbers: decimals, `a/b`, `\frac`, `%`, scientific notation, `x =` / "about" prefixes, with a
    tolerance taken from the key's or the answer's decimals.
  - Symbolic equality: agreement at 8 seeded points.
  - Everything runs on a recursive-descent parser compiled to closures. It never calls `eval` and
    allows ≤ 200 characters, depth ≤ 40 and ≤ 4 variables. Names longer than 3 letters are prose,
    and prose such as "yes" vs "no" is not compared symbolically.
  - Anything unreadable is `None`, never wrong.
- **Key audit**:
  - When the question contains exactly one closed numeric expression (a `$…$` span or a numeric run
    not glued to variables), it is evaluated and compared with a numeric key.
  - A mismatch sets `key_status=wrong` and the grade uses the recomputed value; for mcq, the matching
    option, if exactly one matches.
  - Elephant's `key_valid=invalid` (p ≥ 0.5) can only raise an `ok` key to `suspect`.
- **Labeling** (`decisions.EvidenceLabeler`, System One `choice` questions):
  - It asks only the questions still open: `key_valid` always; `outcome` when no verifier decided;
    `miss_class` and `misconception` when the answer is not correct.
  - Misconception candidates are `none`, `other`, the check's wrong options (`<concept>/<slug>`) and
    misconceptions already seen for that concept this session (at most 8).
  - A field is taken only at a top probability of at least 0.5. An outcome below 0.5 leaves no
    observation (`failed/label_uncertain`).
  - `labeler=baseten` if the model set any field, with `label_confidence` = the minimum taken
    probability.
- **Bounds**:
  - 2 concurrent labels per event loop, an 8 s timeout plus 2 s guard, no retry.
  - The budget is charged before the call, in the shared `learning_budgets` table: 60 per owner and
    300 globally per hour.
  - A missing key records `labeler_not_configured` and charges nothing.
  - A 30 s row lease means two processes never label one row.
- **Failure codes** on the row: `provider_auth_failed` (401/403), `provider_timeout`,
  `provider_rate_limited`, `provider_http_error`, `provider_invalid_response`, `label_budget`,
  `label_uncertain`, `labeler_not_configured`. Logs carry the observation id and code only. A
  failed label keeps the deterministic observation when there is one.
- **Trace**: `GET /learning/sessions/{sid}/evidence` (owner only, proxied) returns rows with status,
  modality, `key_status`, error, `label_ms`, duplicates, verifier, observation and per-field label
  provenance, plus `profile_updated: false`. It is for H8's trace drawer; there is no UI in H4.
- **Predict concept**: a predict has no concept. It takes the latest check concept in the session,
  else `topic:<slug of its turn's first goal>`, with `dimension=understand`.
- **Format weight**:
  - predict 0.5;
  - mcq `1 − 1/n`;
  - free 1.0;
  - × 0.9 when spoken or ink;
  - × 0.5 for a reveal.
- **Profile**: nothing writes a profile, and `profile_updated` stays false.

## Contract changes (H0 surface)

- `learner_contracts.Observation` gains `format_weight: Probability = 1.0` and
  `key_status: "ok" | "suspect" | "wrong" = "ok"`. The TypeScript mirror is updated, and the
  attention-arc fixture still validates through the defaults.
- `TurnInput` gains `via: tap | typed | spoken | ink` (optional) and `element_ids` (ink only).
  `grade()` now returns `verified`, `method`, `key_status`, `recomputed` and `corrected_key`
  alongside the old fields; the stored turn `outcome` carries them. The SSE `turn` event is
  unchanged (`qid`, `result`).
- New table `learning_observations` and new route `GET /learning/sessions/{sid}/evidence`.
- The move schema and the prompt file are unchanged.

## Open issues and notes for later slices

- **User action:** enable decision-model access for the Baseten key (or give a key that has it),
  then run the live script and add the results here.
- **H5**:
  - Read `observation_json` from rows with an observation (status `deterministic`, `labeled`, or
    `failed` with a deterministic outcome).
  - Skip `key_status=wrong`, down-weight `suspect`, and multiply evidence by `format_weight`.
  - Rows `pending` or `failed` without an observation can be re-labeled at close within the same
    budget: reset the status to `pending` and call `observations.label`.
  - Misconception ids are `<concept>/<option-slug>`.
- **Key audit limits:** it only sees closed numeric expressions. A question like "what is 3² + 4²
  under a root" whose key is the root would be flagged wrongly. The tutor gets a note rather than an
  override of its feedback, which limits the damage.
- **Ink answers:** server-side support only; the card has no "answer in ink" control (H7/H8).
- **Widget interactions** are still not evidence.
- **Labels wait in memory:** a process restart drops a scheduled label and leaves its row `pending`.
  H5's re-label at close covers this.
